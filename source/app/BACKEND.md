# 백엔드 연결 가이드 (2026-10-22 통합판)

UI와 백엔드는 `bridge.py`의 `SoundBridge` 하나로만 연결돼요. 백엔드는 Qt 화면을 직접 건드리지 말고 **Signal만** 쓰면 돼요.

```
real_backend.py (3모드 엔진)  ──sound_received──▶  UI(칸 배정·표시)
                              ──backend_status──▶  UI(메인 탭 상태 줄)
real_backend.py               ◀──settings_changed──  UI(사용자 설정, [설정 저장]·모드 전환 때)
real_backend.py               ◀──service_toggled───  UI(서비스 시작/중지)
```

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `main.py` | 앱. 실행하면 `RealBackend`를 붙이고 모델을 **한 번만** 올림 (백그라운드) |
| `real_backend.py` | 앱용 백엔드 스레드. 캡처 → 지금 모드 판정 → 고르기 → emit |
| `sound_engine.py` | 3모드 공통 엔진. 모델 로딩, 판정기 3개, 표시(의성어), 프론트용 고르기 |
| `sound_live_all.py` | 터미널 실행 `--mode gun|horror|variety` (예전 3개 파일 기능 전부) |
| `*_labels.py`, `*_judge.py` | 각 모드 라벨·판정. **계산은 이 파일들 그대로** |
| `sound_live_gun/horror/variety.py` | 예전 모드별 실행 파일. 그대로 둠 (비교용) |

## 1. 모드

- 프론트의 `base_mode`로 판정기를 고름: `FPS` → 총게임, `공포` → 공포게임, `예능` → 예능, `아동` → 아동 (2026-11-05). 프리셋은 자기 `base_mode`를 씀.
- 모드 타일·Alt+M·프리셋 선택은 모두 `commit_settings()` → `settings_changed`로 전달돼요.
- 모드가 바뀌면 그 모드 판정기의 이전 상태(지속음 유지·음악 분위기)를 지우고 시작해요.
- 재생이 멈췄을 때 규칙은 각 모드 CLI와 같아요: 공포·예능은 상태 초기화, 총게임은 그대로.

## 2. 보내는 소리 (백엔드 → UI)

```python
SoundEvent(label="총성 탕!", kind="instant", key="gunshot", category="5-8",
           direction="right", score=0.82)
```

| 필드 | 값 |
|---|---|
| `label` | 표시명. 의성어 켜짐이면 `표시명 의성어` (예: `문 소리 끼익…`), 꺼짐이면 표시명만 |
| `kind` | 판정기가 정한 순간음 / 지속음 |
| `key` | 라벨 키 (예: `gunshot`). 소리 필터 `sounds_off` 와 비교하는 값 |
| `category` | 분류 코드 (라벨 파일의 `cat`, 예: `5-8` = 폭발·총기·불꽃놀이) |
| `direction` | 순간음만 좌우 판정 (`left`/`right`, 구분 안 되면 `center`). 지속음은 항상 `center` |
| `score` | 판정 점수 |
| `count` | **폐지.** 반복 횟수 표기 없음 → 항상 1 (호환용으로 필드만 남음) |
| `strength` | **폐지.** 굵기 구분 없음 → 항상 1 (호환용으로 필드만 남음) |
| `confidence` | 쓰지 않음 (민감도 폐지) → 항상 1.0 |

순간음은 판정에 잡히는 동안 0.5초마다, 지속음도 울리는 동안 0.5초마다 emit 해요 (분석 간격 0.5초).

## 3. 칸 수와 소리 필터 (2026-10-24: 3단 토글)

1. 계산은 지금 로직 그대로 다 해요 (꺼 둔 소리도 계산에 들어감 → 다른 소리 점수에 영향 없음).
2. 판정 순위대로 위에서 **프론트 칸 수**(`instant_slots`, `continuous_slots`)만큼 잘라요.
3. 그중 **꺼 둔 라벨**(`sounds_off`에 키가 있는 것)은 그 자리에서 탈락. 빈자리를 아래 순위 소리로 **채우지 않아요** (오답률 때문).

### 화면에 뜨는 단위 = 모드 라벨

- 화면에 뜨는 건 AudioSet 527개도, CLAP 문장도 아니고 **라벨 파일의 라벨**이에요 (총 모드 17개, 공포 20개, 예능 17개).
  라벨 하나 안에 CLAP 문장(`prompts`)과 AudioSet 라벨(`audioset`)이 같이 들어 있고, 판정기가 둘을 합쳐 라벨 하나를 내요.
- 그래서 끄고 켜는 맨 아래 단위도 이 라벨이에요. `분류.txt`(AudioSet 527 정리)는 **폴더 이름표**로만 써요.

### 토글 구조: 대분류 > 중분류 > 소리

```
1. 사람                       ← 대분류 (분류.txt 이름)
   1-5 움직임·손동작·군중     ← 중분류 (분류.txt 이름)
       발소리                 ← 소리 = 모드 라벨 (footsteps)
5. 생활 속 사물과 기계
   5-8 폭발·총기·불꽃놀이
       총성 · 폭발음 · 연막탄 소리 …
```

- 라벨마다 `cat`(중분류 코드)을 라벨 파일 맨 아래 `CAT` 블록에 적어요. 이름표는 `sound_tree.CATS`.
- 트리는 `sound_tree.build_tree(base_mode)`가 **모드마다** 만들어요. 그 모드 라벨이 하나도 없는 칸(예: 총 모드의 동물·음악)은 안 보여요.
- 흡수 라벨(`kind="sink"`: 목소리·기타 등)은 화면에 안 뜨니 토글도 없어요.
- 토글 이름이 같은 라벨은 토글 하나예요 (공포 `door`+`knock` = 문 소리). 1등 문장에 따라 이름이 두 개로 뜨는 라벨은 `TOGGLE_NAME`으로 합친 이름 (공포 `impact` = 문 닫힘·물건 떨어짐, `chain` = 쇠사슬·쇠 긁힘).
- 확인: `python sound_tree.py` → 세 모드 트리 출력.

### 프론트 → 백엔드: 꺼 둔 라벨 키 목록만

```python
"sounds_off": ["bullet_whiz", "explosion", "smoke", "flashbang", "grenade_pin"]
```

- 대분류·중분류 토글은 **프론트에서만** 계산해요. 끄면 그 아래 라벨 키를 전부 넣고, 켜면 전부 빼요. 아래가 일부만 꺼져 있으면 부모는 켜짐 + `일부 꺼짐 (n/m)`.
- 백엔드는 트리를 몰라요. `select_for_front()`가 결과의 `key`가 `sounds_off`에 있으면 버려요.
- 설정이 모드(·프리셋)마다 따로 저장되니 `sounds_off`도 모드마다 따로예요 (총 모드에서 발소리를 꺼도 공포 모드 발소리는 그대로).
- `settings.normalize()`가 그 모드에 없는 키는 지워요. 예전 10개 그룹 설정(`sounds`)은 버리고 전부 켜짐으로 시작.
- 분류표를 다시 짜도 라벨 키는 그대로라 저장된 설정이 안 깨져요.

### 라벨을 새로 추가할 때

라벨 파일 `LABELS`에 넣고, 같은 파일 `CAT`에 중분류 코드를 넣으면 끝 (`cat`이 없으면 `build_tree`가 오류를 내요).

## 4. 의성어

- 설정 키 `onoma_enabled` (기본 켜짐). 화면: 세부 커스터마이징 → 자막 표시 칸 세팅 → **의성어 표시**
- 라벨 파일 맨 아래 블록에서 관리: `ONOMA`(기본 의성어), `PROMPT_ONOMA`(1등 문장별 의성어), `CAT`(분류 코드), `TOGGLE_NAME`(필터 토글 이름)
- 1등 문장에 따라 이름이 바뀌는 라벨(공포 쾅 → `문 닫히는 소리`/`물건 떨어지는 소리`, 공포 쇠사슬 → `쇠 긁히는 소리`)은 `prompt_names`
- 표시명 변경: 예능 `땡 부저`→`오답`, `쾅 치는 소리`→`책상 치는 소리` / 공포 `쾅`→문장별, `문 끼익 소리`→`문 소리`(+끼익…), `물 떨어짐`→`물방울`, `점프 스케어`→`깜짝 효과음`, 쇠사슬 긁는 문장→`쇠 긁히는 소리`

## 5. 백엔드가 쓰는 설정 키

| 키 | 내용 |
|---|---|
| `base_mode` | `FPS` / `공포` / `예능` |
| `instant_slots`, `continuous_slots` | 칸 수. 위에서 이만큼 자름 |
| `instant_enabled`, `continuous_enabled` | 꺼져 있으면 그 종류는 안 보냄 |
| `sounds_off` | 꺼 둔 라벨 키 목록 (모드마다 따로) |
| `onoma_enabled` | 의성어 붙일지 |

설정은 **[설정 저장]**을 누르거나 모드를 바꿀 때 백엔드로 가요 (예전과 같음).

## 6. 백엔드 없이 시험하기

`테스트 소리 자동 생성` 스위치를 켜면 `fake_backend.py`가 가짜 소리를 보내요. 켜져 있는 동안 실제 백엔드는 소리를 보내지 않아요.

## 7. 성능 기록 (2026-10-25, 테스트 실행 때만)

평소 `run_app.bat`은 기록하지 않아요. 아래 두 실행 파일로 켤 때만 `perf_logs\`에 파일이 생겨요. 한 번의 기록 = [서비스 시작] ~ [서비스 중지] (앱을 끄면 그때까지 저장).

| 실행 파일 | 하는 일 | 파일 |
|---|---|---|
| `성능기록_실행.bat` (`main.py --perf`) | 평소처럼 쓰면서 분석마다 ④~⑧ 단계 시간·CPU·메모리·표시한 소리·필터로 빠진 소리 | `perf_시각.csv` + `_요약.txt` |
| `지연시험_실행.bat` (`main.py --latency-test 30`) | 앱이 '딱' 시험음을 30번 재생해 ①~⑧ 전 단계를 실측 (다른 소리는 끄고) | `latency_시각.csv` + `_요약.txt` |

단계: ① 오디오 엔진 통과 → ② 루프백 전달 → ③ 분석 대기 → ④ 처리(캡처 복사, 모델별 리샘플·전처리·추론, 기타, 돌발성, 판정) → ⑤ 고르기 → ⑥ UI 전달 → ⑦ 오버레이 배치 → ⑧ 화면 그리기. ①~③은 지연 시험에서만 잴 수 있어요.

- 지연 시험 중에는 시험음마다 `⏱ 시험음 #번호` 자막이 같은 경로로 떠요 (모델이 '딱'을 아무 소리로도 판정하지 않을 수 있어서). 그 순간 모델이 실제로 판정한 소리는 CSV 마지막 칸에 남아요.
- 모델 3개는 동시에 돌아서 모델별 시간을 더하면 ④보다 클 수 있어요. 모니터 갱신 시간(60Hz면 최대 약 17ms)은 못 재요.
- CPU·메모리는 `psutil`이 필요해요 (두 bat 파일이 없으면 설치).
- 코드: `perf_log.py`, `real_backend.py`(`_emit_logged`), `main.py`(`on_sound`, `PaintWatch`)
